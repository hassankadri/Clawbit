# Clawbit backend

Use the [root setup guide](../README.md) for current installation, environment,
startup, evaluation and CI instructions. Python 3.12.3 is the verified local/CI
baseline; `requirements-lock.txt` pins the installed dependency snapshot.

## Existing installation

The owner and legacy resource claim are already initialized. Do not repeat
`setup_owner.py` or `ownership_migration.py` during ordinary startup.

```powershell
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000 --no-access-log
```

Sign in through the frontend with the existing account. Use one worker because
connector credentials and OAuth state are process-local. Restart requires
reconnection, not replacement keys. Preserve the runtime root and all backups.

## Fresh installation only

Create a Python 3.12 virtual environment, then run:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt -r requirements-lock.txt
.\.venv\Scripts\python.exe setup_owner.py
```

Owner setup uses hidden interactive passphrase entry. No public registration or
default credentials exist. Read the [ownership report](../docs/BATCH_4B_1_OWNERSHIP.md)
before planning any legacy claim; the configured installation needs none.

## Diagnostics

`CLAWBIT_LOG_LEVEL` controls bounded JSON events from the `clawbit` logger.
`X-Request-ID` is generated by the server and propagated through async graph and
worker operations. Logs exclude resource IDs, prompts, credentials, headers and
provider bodies. DEBUG includes only bounded frame locations. Keep HTTP access
logs and SDK body tracing disabled, especially around OAuth callbacks.

## Web fetching and external-content security (Batch 3)

`read_webpage` accepts public HTTP/HTTPS HTML and plain text. It rejects credentials,
invalid URLs/ports and non-public IPv4/IPv6 targets. Every DNS answer must pass the
address policy. The socket connects to a validated numeric address, without a
second hostname lookup, while HTTPS keeps default certificate verification and
the original hostname for SNI/hostname checks. It never uses environment proxies,
cookies, automatic redirects or URL credentials. Up to three redirects are followed,
with each destination resolved and checked again, including same-host redirects.

Connection and socket-read timeouts are five seconds. Body reads additionally
check a 20-second deadline between reads. Both wire content and decompressed
content are limited to 1 MiB. Gzip and zlib-wrapped deflate are decoded with a
bounded output buffer; unsupported encodings, concatenated gzip members and
malformed/truncated streams are rejected. HTML scripts/styles/navigation and
other non-content elements are removed. The existing 5,000-character text budget
is retained, with the final public source URL included for citations. No dependency
was added or upgraded.

All tool results, including search, RAG, memory and MCP responses, are represented
to the model as JSON-encoded untrusted data within their original `ToolMessage`
role. Literal closing tags and role sentinels are escaped; source text is never
parsed into messages, consent or tool calls. Tool-call IDs, document citation
artifacts, stored history and supported non-text MCP blocks remain intact.
Only the server supplies the system message. Research mode retains the latest
real user request even after its recent-message window fills with tool results.
Document query rewriting also separates server instructions from encoded context.
Tool failures are reported explicitly without raw exception messages or headers.

The trusted prompt instructs the model to use external content as evidence, not
commands, and to derive further tool use from the actual user request. This is
**not deterministic semantic prompt-injection prevention**: JSON encoding and
message roles enforce representation, but a model can still misinterpret hostile
data or produce an unwanted tool call. The agent's existing tool execution model
is preserved; no new per-action authorization system is introduced. For deployments
with sensitive/write-capable connectors, enforce least-privilege credentials and
independent approval/authorization controls for consequential actions.

SSRF protection assumes a trustworthy OS routing/TLS environment. Public addresses
can be routed to internal services by local NAT, tunnels or infrastructure outside
this process. Registry-based IP classification is conservative; transition ranges
are denied. OS DNS resolution and slow response-header parsing are not bounded by
the body deadline. Deploy network-level egress restrictions blocking private,
metadata and special-use networks, including IPv6, and use controlled DNS and
appropriate process/request resource limits. These restrictions should also cover
other connectors; this fetcher does not proxy or sandbox arbitrary MCP services.
